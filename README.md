# Инструменты наполнения товарного каталога

Три скрипта, которыми товарный каталог наполняется от поискового спроса:
строка таблицы → снимок с официальной страницы производителя → ориентировочная
цена. Вынуты из боевого проекта — корпоративного сайта поставщика оборудования,
где ими заведено полторы сотни позиций и рассчитано на тысячи.

Задача звучит просто — «залить товары в каталог», — но у неё есть три
неочевидных ограничения, и почти весь код здесь про них.

---

## Ограничение первое: выгрузки нет и не будет

У компании нет постоянных поставщиков, а договориться с дистрибьютором —
решение директора, а не исполнителя. Значит, машинной выгрузки товаров
не появится, и рассчитывать надо на порядок, который работает без неё:

```
частоты Яндекс.Вордстата  →  что вообще ищут
        ↓
официальная страница производителя  →  артикул и характеристики
        ↓
add-rows.mjs   →  строка в таблице товаров
        ↓
photos.mjs     →  снимок оттуда же
        ↓
prices.mjs     →  ориентировочная цена с датой проверки
```

Порядок повторяемый: последняя партия из 40 позиций закрыта снимками
на 100% и ценами на 97,5% за один проход, без ручной доработки.

## Ограничение второе: снимок нельзя взять из магазина

Соблазн очевидный — в карточке DNS или «Ситилинка» снимок уже красивый,
на белом фоне, нужного размера. Брать его нельзя, и дело не в осторожности:

- **это чужое произведение.** Карточку снимает и обрабатывает сам магазин;
  охрана возникает с момента создания, без всякой регистрации. Компенсация
  по ст. 1301 ГК — от 10 000 до 5 000 000 ₽ **за каждое изображение**.
  На каталоге в тысячу позиций это не абстракция;
- **«изменить пиксели» не помогает.** Обрезка, перекраска фона, поворот,
  пережатие — это переработка (ст. 1270 ГК), отдельное правомочие
  правообладателя. Переработанный без разрешения снимок нарушает право так же,
  как копия, только ещё и доказуемо: совпадают композиция, свет, положение
  предмета;
- **и отдельно — поиск.** Тот же снимок, что у крупного магазина, поисковик
  опознаёт как дубль. Каталог делается ради выдачи, класть в него заведомые
  дубли — работать против собственной цели.

Поэтому `photos.mjs` ходит **только по списку сайтов производителей**
(`MANUFACTURERS` в начале файла). Магазины перечислены отдельным списком
`SHOPS` — не чтобы запретить, а чтобы отказ был внятным: «dns-shop.ru —
витрина магазина, снимки оттуда не берём».

## Ограничение третье: неверный снимок хуже отсутствующего

Отсутствующий видно сразу, неверный — нет. Поэтому сопоставление
консервативное, и порядок в нём выстрадан:

1. **артикул в имени файла** — `TN2375_main.webp`, `TK1170.png`. Надёжнее всего;
2. **ресурс в страницах** — Pantum называет файл `4020-6000-1png.png`,
   «платформа 4020, 6000 страниц». Засчитывается только у расходников:
   у аппарата «30 стр./мин» — число из другой оперы;
3. **`og:image` на странице, где заведомо один товар** (`ONE_PRODUCT_PAGES`) —
   так закрываются HP, MSI, Xiaomi, LG и Acer: они держат снимки под кодами
   вида `uzoubfclhe.png`, совпасть с артикулом те не могут в принципе;
4. **правило сайта** (`SITE_RULES`) — сильнее всего остального.

Чего скрипт **не** делает:

- **не берёт совпадения по одним цифрам артикула.** На проверке 84 позиций
  такое трижды подставило чужой снимок: `TL-420HP` получил картинку
  от `TL-420X`, фотобарабан `DL-420` — картинку тонера;
- **не берёт молча сомнительное.** Всё, что нашлось, но не подтвердилось,
  уходит в отчёт «посмотрите глазами» со ссылкой — и скачивается только
  с явным `--loose`;
- **ловит заглушки.** Один и тот же файл у разных позиций — признак картинки
  «тонер вообще»: так поймались два картриджа Xerox с общим
  `TONER_600x600.jpg`.

### Правила под отдельные сайты

Сайты ведут себя по-разному, и `SITE_RULES` — это место, где записано,
как именно. Каждое правило с объяснением: через полгода никто не вспомнит,
откуда взялся регэксп.

| Случай | Что пришлось учесть |
|---|---|
| Магазин производителя отдаёт **404 при полном содержимом** | признак `anyStatus` |
| Код модели стоит и в адресах **рекламных баннеров** | правило сайта отменяет совпадение по артикулу |
| Одна страница держит **весь ряд ёмкостей** (1–6 ТБ) | правило может быть функцией от позиции: нужный кадр выбирается по ёмкости из наименования |
| Производитель снимает **корпус, а не ёмкость** — один снимок на 1 и 2 ТБ | признак `sharedImage`: повтор адреса у таких позиций законен и заглушкой не считается |
| В `og:image` **рекламный баннер**, а снимок лежит рядом | правило указывает, где именно |
| Библиотека Scene7 отдаёт **400 px по умолчанию** | тот же адрес с `wid=1200` даёт 1200 — это та же картинка в другой рендиции |

Формат на выходе один для всех: квадрат на белом, сторона 600–1000 px
под исходник, JPEG до 220 КБ. Квадрат одинаковый не из эстетства — иначе
сетка раздела выглядит как свалка из чужих карточек.

**Происхождение фиксируется.** У каждого снимка в `catalog/seed/photos.json`
записано: с какой страницы, по какому адресу, когда снят, отпечаток файла.
Через полгода на вопрос «откуда это фото» есть ответ.

## Цены: их собирает человек.

`prices.mjs` не собирает цены. Он делает **лист**: одна строка — одна позиция,
рядом готовые адреса поиска. Человеку остаётся открыть ссылку и вписать число.

Так — потому что выгружать прайс магазина скриптом нельзя (это уже
не «число как факт», а использование чужой витрины) и технически бесполезно:
«Ситилинк» разбивает цифры цены по элементам и подмешивает невидимые символы
именно против такого чтения. У DNS цена лежит в разметке `Product` и читается
человеком и инструментом одинаково — поэтому порядок такой: сначала DNS,
нет — «Ситилинк» глазами, нет — любой другой магазин.

Три обязательных условия:

1. **дата проверки.** На карточке видно: «Ориентировочная цена на 29.09.2026».
   Цена без даты через полгода превращается в дезинформацию;
2. **оговорка рядом** — конечную стоимость, наличие и срок уточняйте;
3. **источник цены — внутрь, не на страницу.** Называть чужой магазин
   на своей карточке незачем; поле нужно тому, кто будет цену перепроверять.

`--apply` переносит заполненное обратно в таблицу. Таблица пересобирается
целиком, поэтому перед записью делается проверка обратным разбором:
**не сошлась хоть одна ячейка — не пишется ничего.**

## Как запустить

```bash
npm install
npm run photos                 # отчёт: что найдётся, ничего не пишет
npm run photos -- --write      # скачать, привести к формату, сохранить
npm run prices -- --list       # собрать лист цен на заполнение
npm run prices -- --apply      # перенести заполненное обратно в таблицу
```

В репозитории лежит таблица-образец из трёх позиций (`catalog/seed/tovary.csv`)
со ссылками на настоящие страницы Western Digital, Toshiba и Logitech —
`npm run photos` работает сразу после клонирования.

Полный список ключей — в шапке каждого скрипта, там же объяснено, зачем он.

### Раскладка

```
catalog/
  seed/
    tovary.csv        таблица товаров — её ведут руками в Excel
    products.json     реестр таблиц; позиции, заведённые не таблицей
    photos.json       происхождение снимков, ведёт photos.mjs
  import/
    template.csv      пустой шаблон таблицы с подсказками
    ceny.csv          лист цен, собирается prices.mjs
  public/assets/products/   снимки, <адрес позиции>.jpg
scripts/
  add-rows.mjs        дописать партию позиций в таблицу
  photos.mjs          снимки с официальных страниц
  prices.mjs          лист цен и перенос заполненного
```

Таблица — CSV с разделителем «;», UTF-8 с BOM, переносы внутри ячеек:
так её открывает и сохраняет Excel, а таблицу ведёт заказчик, а не скрипт.
`add-rows.mjs` только дописывает строки в конец и никогда не пересобирает
файл целиком — правки, сделанные руками, остаются на месте.

## Чего здесь нет и почему

**Смоук-теста боевой выкладки.** В исходном проекте есть ещё один инструмент —
119 проверок живого сайта: коды ответов, канонические адреса, следы ошибок PHP,
закрытость служебных папок, карточка товара со снимком и ценой, приём заявок.
Каждая проверка там появилась после того, как что-то сломалось.

Он остался в закрытом репозитории, потому что на 40% состоит из бизнес-правил
конкретного заказчика — какие реквизиты сняты с сайта, каких слов на нём быть
не должно, какой файл подтверждения прав удалять нельзя. Обезличить его —
значит выпотрошить.

**Самого сайта и каталога.** Это чужой коммерческий продукт. Здесь только
инструменты, которые не содержат данных заказчика: ни реквизитов,
ни инфраструктуры, ни цен.
